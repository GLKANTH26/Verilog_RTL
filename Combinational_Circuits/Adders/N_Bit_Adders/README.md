# N-Bit Adders

This directory contains a **parameterized N-bit Full Adder implemented in Verilog**, demonstrating how a single-bit Full Adder can be reused to construct a scalable multi-bit binary adder.

The implementation uses **structural module instantiation and Verilog `generate` constructs** to create an array of Full Adder stages connected through a carry chain.

---

## 1. N-Bit Full Adder

The `n_bit_fa` module performs binary addition of two `N`-bit operands along with an input carry.

### Inputs

* `a[N-1:0]` — First N-bit operand
* `b[N-1:0]` — Second N-bit operand
* `c_in` — Input carry

### Outputs

* `sum[N-1:0]` — N-bit sum
* `c_out` — Final carry-out

The module is parameterized using:

```verilog
parameter N = 8
```

Therefore, the same module can be configured for different operand widths without rewriting the design.

---

## 2. Architecture

The N-bit adder is implemented as a **ripple-carry adder**.

Each bit position contains one Full Adder:

```text
                 ┌──────────────┐
a[0] ───────────►│              │
b[0] ───────────►│  Full Adder  │────► sum[0]
c_in ───────────►│     FA₀      │
                 └──────┬───────┘
                        │ carry[1]
                        ▼
                 ┌──────────────┐
a[1] ───────────►│              │
b[1] ───────────►│  Full Adder  │────► sum[1]
                 │     FA₁      │
                 └──────┬───────┘
                        │ carry[2]
                        ▼
                       ...
                        │
                        ▼
                 ┌──────────────┐
a[N-1] ─────────►│              │
b[N-1] ─────────►│  Full Adder  │────► sum[N-1]
                 │   FA[N-1]    │
                 └──────┬───────┘
                        │
                        ▼
                      c_out
```

The carry generated by each Full Adder becomes the carry input of the next stage.

Thus:

```text
c_in → FA₀ → FA₁ → FA₂ → ... → FA[N-1] → c_out
```

## 3. Instantiation of the Previously Developed Full Adder

The implementation does **not redefine the Full Adder inside the N-bit module**.

Instead, the previously developed `Full_adder.v` module is included:

```verilog
`include "Full_adder.v"
```

and instantiated inside the `generate` loop:

```verilog
full_adder fa(
    a[i],
    b[i],
    carry_chain[i],
    sum[i],
    carry_chain[i+1]
);
```

This is an example of **hierarchical and reusable RTL design**.

The existing Full Adder becomes a building block for the larger N-bit adder.

### Module Relationship

```text
full_adder
     │
     │ instantiated N times
     ▼
┌──────────────────────────────────┐
│            n_bit_fa               │
│                                  │
│ FA₀ → FA₁ → FA₂ → ... → FA[N-1] │
│                                  │
└──────────────────────────────────┘
```

For `N = 8`, the elaborated design contains **8 Full Adder instances**.

---

## 4. Carry Chain

The internal carry chain is declared as:

```verilog
wire [N:0] carry_chain;
```

This requires `N+1` carry positions.

The first position receives the external input carry:

```verilog
assign carry_chain[0] = c_in;
```

Each Full Adder consumes one carry and produces the next:

```text
carry_chain[i]
       │
       ▼
   Full Adder
       │
       ▼
carry_chain[i+1]
```

Finally:

```verilog
assign c_out = carry_chain[N];
```

Therefore:

```text
carry_chain[0] = c_in

carry_chain[1] = carry generated by FA₀
carry_chain[2] = carry generated by FA₁
...
carry_chain[N] = carry generated by FA[N-1]

c_out = carry_chain[N]
```

---

## 5. Generate Loop

The Full Adder instances are created using a Verilog `generate` loop:

```verilog
genvar i;

generate
    for (i = 0; i < N; i = i + 1) begin : fa_stage
        full_adder fa(
            a[i],
            b[i],
            carry_chain[i],
            sum[i],
            carry_chain[i+1]
        );
    end
endgenerate
```

The `generate` construct allows the hardware structure to be **replicated at elaboration time**.

For:

```verilog
N = 8
```

the generated hardware is conceptually:

```text
FA₀ → FA₁ → FA₂ → FA₃ → FA₄ → FA₅ → FA₆ → FA₇
```

This avoids manually writing eight separate Full Adder instantiations.

# 6. Independent N-Bit Adder Without Full Adder Instantiation

The N-bit adder can also be implemented **independently without instantiating the previously developed `full_adder` module**.

In that approach, the Full Adder equations are described directly inside the N-bit module.

For each bit:

```text
sum[i]      = a[i] ⊕ b[i] ⊕ carry[i]

carry[i+1]  = a[i]b[i] + carry[i](a[i] ⊕ b[i])
```

A corresponding implementation can be written as:

```verilog
module n_bit_fa #(parameter N = 8)(
    input  [N-1:0] a,
    input  [N-1:0] b,
    input          c_in,
    output [N-1:0] sum,
    output         c_out
);

    wire [N:0] carry;

    assign carry[0] = c_in;

    genvar i;
    generate
        for (i = 0; i < N; i = i + 1) begin : fa_stage

            assign sum[i] =
                a[i] ^ b[i] ^ carry[i];

            assign carry[i+1] =
                (a[i] & b[i]) |
                ((a[i] ^ b[i]) & carry[i]);

        end
    endgenerate

    assign c_out = carry[N];

endmodule
```

### Difference Between the Two Approaches

| Approach                        | Description                                                           |
| ------------------------------- | --------------------------------------------------------------------- |
| **Hierarchical / Instantiated** | Reuses the previously designed `full_adder` module                    |
| **Independent**                 | Directly implements the Full Adder equations inside each bit position |
| **Code Reuse**                  | High in hierarchical approach                                         |
| **Module Dependency**           | Hierarchical approach depends on `Full_adder.v`                       |
| **Self-contained**              | Independent implementation is self-contained                          |
| **Maintainability**             | Hierarchical approach is easier to reuse and maintain                 |
| **Learning Value**              | Independent implementation exposes the underlying equations directly  |

The current implementation uses the **hierarchical approach**, which is generally preferable when building a library of reusable RTL modules.

---

# 7. Why Module Instantiation Is Useful

Reusing the previously developed `full_adder` provides several advantages:

### Modularity

The Full Adder is designed and verified independently.

### Reusability

The same Full Adder can be used in:

* N-bit adders
* Ripple-carry adders
* Arithmetic units
* ALUs
* Larger datapaths

### Verification Reuse

Once the `full_adder` has been thoroughly verified, the N-bit design can build upon that verified block.

### Hierarchical Design

Large digital systems can be constructed from smaller verified modules.

```text
Gate
 ↓
Half Adder
 ↓
Full Adder
 ↓
N-Bit Adder
 ↓
ALU / Datapath
```

# 8. Verification

The testbench instantiates an **8-bit configuration** of the parameterized N-bit Full Adder:

```verilog
localparam W8 = 8;

n_bit_fa #(W8) nfa(
    a8,
    b8,
    cin8,
    sum8,
    cout8
);
```

Three representative test cases are applied:

| `a` | `b` | `c_in` | Expected Operation     |
| --: | --: | :----: | ---------------------- |
|   5 |   2 |    0   | 5 + 2                  |
| 100 |  50 |    1   | 100 + 50 + 1           |
| 255 |   1 |    0   | Overflow demonstration |

The final test case demonstrates carry-out behavior because:

```text
255 + 1 = 256
```

For an 8-bit output:

```text
256 = 1 0000 0000
      │ └──────┘
     c_out   sum[7:0]
```

Therefore:

```text
sum  = 8'b00000000
c_out = 1
```

## Key Design Principle

The implementation demonstrates two fundamental approaches to constructing larger RTL blocks:

```text
                    N-BIT ADDER
                         │
             ┌───────────┴───────────┐
             │                       │
             ▼                       ▼
      Hierarchical Design      Independent Design
             │                       │
     Instantiate FA             Implement FA
             │                    Equations
             ▼                       ▼
       Reuse Verified            Self-Contained
       Full Adder Block             RTL
```

The current implementation follows the **hierarchical and modular approach**, using the previously developed Full Adder as a reusable building block and replicating it `N` times through a `generate` construct.
`include "n_bit_fa.v"

module n_bit_fa_tb;

  localparam W8 = 8;
  reg [W8-1:0] a8,b8;
  reg cin8;
  wire [W8-1:0] sum8;
  wire cout8;

  n_bit_fa #(W8) nfa(a8,b8,cin8,sum8,cout8);

  initial begin
    $fsdbDumpvars();

    $monitor("T=%0t a=%d b=%d c_in=%b sum=%d c_out=%b",$time, a8,b8,cin8,sum8,cout8);          
    a8=5;b8=2;cin8=0;
    #10;
    a8=100;b8=50;cin8=1;
    #10;
    a8=255; b8=1;cin8=0;
    #10;
    $finish;
  end
  
endmodule
