# N-Bit Add/Subtract Unit

This directory contains a **parameterized N-bit Add/Subtract Unit implemented in Verilog HDL**.

The design extends the single-bit **Full Adder / Full Subtractor (`fa_fs`)** developed in the `Add_Subtract_Unit` directory into a scalable multi-bit arithmetic unit.

A single control signal selects between:

* **Addition**
* **Subtraction**

The design uses a **generate loop** to instantiate the required number of single-bit `fa_fs` stages and connects them through a carry/borrow chain.

# 1. N-Bit Add/Subtract Operation

The `n_bit_fa_fs` module performs either:

```text id="2q4w87"
A + B
```

or:

```text id="a7phxw"
A - B
```

depending on the value of the control signal `sub`.

| `sub` | Operation   | `res`      | `cout`     |
| :---: | ----------- | ---------- | ---------- |
|  `0`  | Addition    | Sum        | Carry-out  |
|  `1`  | Subtraction | Difference | Borrow-out |

Therefore:

```text id="q9b7do"
sub = 0  →  ADD
sub = 1  →  SUBTRACT
```

# 2. Parameterized Design

The module is parameterized using:

```verilog id="t3c7c4"
parameter N = 8
```

The parameter determines the width of the operands and result.

### Inputs

```text id="6g3e1h"
a[N-1:0]
b[N-1:0]
c
sub
```

Where:

* `a` — N-bit first operand
* `b` — N-bit second operand
* `c` — Initial carry/borrow input
* `sub` — Addition/Subtraction control

### Outputs

```text id="1j4w4p"
res[N-1:0]
cout
```

Where:

* `res` — N-bit result
* `cout` — Final carry/borrow output

# 3. Architecture

The N-bit unit is constructed by connecting `N` single-bit **Full Adder / Full Subtractor** stages.

```text id="4b3pmm"
                         sub
                          │
                          │
a[0] ─────┐        ┌────────────┐
b[0] ─────┼───────►│   FA / FS  │────► res[0]
c[0] ─────┘        │    Stage 0 │
                    └─────┬──────┘
                          │ cc[1]
                          ▼
a[1] ─────┐        ┌────────────┐
b[1] ─────┼───────►│   FA / FS  │────► res[1]
cc[1] ────┘        │    Stage 1 │
                    └─────┬──────┘
                          │ cc[2]
                          ▼
                         ...
                          │
                          ▼
a[N-1] ───┐        ┌────────────┐
b[N-1] ───┼───────►│   FA / FS  │────► res[N-1]
cc[N-1] ──┘        │  Stage N-1 │
                    └─────┬──────┘
                          │
                          ▼
                        cout
```

The carry/borrow generated by one stage becomes the input to the next stage.

Thus:

```text id="l4y9fw"
cc[0] → Stage 0 → Stage 1 → ... → Stage N-1 → cout
```

# 4. Instantiation of the Single-Bit FA/FS Module

The N-bit design reuses the previously developed `fa_fs` module from the `Add_Subtract_Unit` directory.

The implementation includes the module:

```verilog id="8v3k6v"
`include "fa_fs.v"
```

and instantiates it inside a `generate` loop.

Conceptually:

```verilog id="gdb1ac"
fa_fs dut(
    a[i],
    b[i],
    cc[i],
    sub,
    res[i],
    cc[i+1]
);
```

This demonstrates **hierarchical and reusable RTL design**.

Instead of rewriting the Full Adder / Full Subtractor logic for every bit, the verified single-bit module is reused as a building block.

---

# 5. Generate Loop

The N-bit architecture uses a Verilog `generate` construct to replicate the `fa_fs` module:

```verilog id="1g5vzs"
genvar i;

generate
    for(i = 0; i < N; i = i + 1) begin : fa_sub_stage

        fa_fs dut(
            a[i],
            b[i],
            cc[i],
            sub,
            res[i],
            cc[i+1]
        );

    end
endgenerate
```

For:

```verilog id="h0x0br"
N = 8
```

the elaborated design contains:

```text id="1y6k9x"
FA/FS₀
FA/FS₁
FA/FS₂
FA/FS₃
FA/FS₄
FA/FS₅
FA/FS₆
FA/FS₇
```

connected through the carry/borrow chain.

# 6. Carry / Borrow Chain

The internal chain is declared as:

```verilog id="h99qmr"
wire [N:0] cc;
```

The initial chain value is determined by:

```verilog id="h1y9k4"
assign cc[0] = c | sub;
```

This allows the same architecture to support both arithmetic modes.

### Addition Mode

When:

```text id="wz2x9q"
sub = 0
```

the initial chain becomes:

```text id="0e0paf"
cc[0] = c
```

and the stages operate as Full Adders.

```text id="mxy8cf"
c → FA₀ → FA₁ → ... → FA[N-1] → cout
```

---

### Subtraction Mode

When:

```text id="7g0d2c"
sub = 1
```

the initial chain becomes:

```text id="axm5vr"
cc[0] = 1
```

and the stages operate as Full Subtractors according to the control logic of `fa_fs`.

```text id="4x3fjw"
Borrow chain → FS₀ → FS₁ → ... → FS[N-1] → cout
```

The final `cout` represents the final carry or borrow behavior according to the selected mode.

---

# 7. Operand and Control Relationship

The same `sub` control signal is supplied to every single-bit arithmetic stage:

```text id="f9q5j8"
                 sub
                  │
        ┌─────────┼─────────┐
        ▼         ▼         ▼
      FA/FS₀    FA/FS₁    FA/FS₂   ...
        │         │         │
        └────┬────┴────┬────┘
             │         │
          Carry/Borrow Chain
```

Thus, the entire N-bit datapath operates in the **same arithmetic mode**.

```text id="yx8ftf"
sub = 0
   ↓
All stages operate as Full Adders
   ↓
N-bit Addition


sub = 1
   ↓
All stages operate as Full Subtractors
   ↓
N-bit Subtraction
```

# 9. Ripple-Cary Architecture

The N-bit implementation forms a **ripple-carry / ripple-borrow architecture**.

The output carry/borrow of each stage must propagate to the next stage before the final result is completely determined.

```text id="u0eq0r"
Stage 0
   │
   ▼
Stage 1
   │
   ▼
Stage 2
   │
   ▼
 ...
   │
   ▼
Stage N-1
   │
   ▼
cout
```

### Important Hardware Characteristic

The architecture is simple and modular, but its worst-case propagation delay increases with `N` because the carry/borrow may need to propagate through every stage.

Conceptually:

```text id="6k7x3u"
More bits
   ↓
More FA/FS stages
   ↓
Longer carry/borrow propagation
   ↓
Higher worst-case combinational delay
```

This is the fundamental limitation of a ripple-carry architecture and motivates faster architectures such as **Carry Look-Ahead Adders** and other optimized arithmetic structures.

## Key Design Principle

The N-bit Add/Subtract Unit demonstrates how a **single verified arithmetic stage can be replicated and interconnected to construct a scalable multi-bit arithmetic datapath**.

```text id="q6cnz0"
        Single-Bit FA/FS
               │
               ▼
        Module Instantiation
               │
               ▼
       Generate N Stages
               │
               ▼
     Carry / Borrow Chain
               │
               ▼
       N-Bit Add/Sub Unit
               │
               ▼
        Arithmetic Datapath
```

The architecture emphasizes **module reuse, parameterization, hierarchical design, and scalability**, forming a foundation for larger arithmetic blocks such as **ALUs, processor datapaths, and other digital processing units**.
